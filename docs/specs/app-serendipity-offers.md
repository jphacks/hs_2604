# APP-13：セレンディピティ販促（ゲリラクーポン・セット割・タイムセール）

対象：[APP-13 / #93](https://github.com/jphacks/hs_2604/issues/93)。作業フェーズ：hackday。関連購買ルールは[APP-04 / #20](../../analysis/app04-association-rules/README.md)を使用。

## 実装方針

- セレンディピティ販促は「かごの商品と関連があり、利用者が自分では探していなかったお得な提案」。通常推薦・店舗販促（INS-02）・メーカー広告とは別枠「いまだけのお得」「ゲリラクーポン」として表示し、店舗のお得情報であることを明示する。
- お得の条件・期間・割引は店舗がDBへ設定する（`store_offers`）。Appは表示順を決めるだけで、割引額を計算・保存しない。割引はDB関数だけが計算し、かご表示・購入確定で同じ値を使う。
- APP-04のルールで、関連の強さ（lift＝意外性）×割引率の順に並べる。店舗がきっかけ商品を指定したクーポンを優先し、指定がないクーポンはかごの商品と関連ルールがある場合だけ出す。
- APP-05〜08（推薦の選定・カード・イベント・再選定）とは独立して動く。選定記録`selections`へは保存しない。

## 3種類のお得と割引

| 種類 | 表示する条件 | 受け取ったとき | 割引の対象 |
| --- | --- | --- | --- |
| ゲリラクーポン | 期間中で、きっかけ商品がかごにある（指定がない場合はAPP-04で関連がある）。対象商品がすでにかごにある場合は出さない | 対象商品を1点かごへ追加 | 対象商品1点 |
| セット割 | 期間中で、きっかけ商品がかごにある | 不足している商品を1点追加（両方あれば適用のみ） | 2商品の少ない方の数量分、両方の商品。どちらかを削除すると外れ、戻すと再適用 |
| タイムセール | 期間中（開始前は表示しない） | 対象商品を追加、またはかご内の商品へ適用 | 対象商品の全数量 |

- 1点あたりの割引は`floor(価格 × 割引率)`または割引額。価格を超えない。同じ商品に複数のお得が該当しても重ねず、割引額が最大の1つだけを適用する。
- 受け取りは来店ごとに1回。受け取った時点で有効なら、その後に期間が終わっても購入確定まで割引を維持する。終了後の新しい受け取りは拒否する（「終了後は新規割引を適用しない」）。
- 受け取ったお得は再表示しない。クーポンの「今回は見送る」は、その来店の間（ブラウザのsessionStorage）表示しない。ステッカーは1回に1枚。

## 接続契約

追加migration：`kago-os/kago-core/supabase/migrations/20261024140000_app_serendipity_offers.sql`。既存テーブルの権限は緩めない。

| テーブル | 内容・権限 |
| --- | --- |
| `store_offers` | 店舗が設定するお得。自店の店舗担当者だけが作成・閲覧・停止（`active`→`inactive`のみ）。条件は作成後に変更不可。利用者は直接読めない |
| `visit_offer_claims` | 来店ごとの受け取り。DB関数だけが作成。変更・削除不可 |
| `order_discounts` | 注文の割引明細（注文・商品・お得・数量・金額）。本人の注文だけ閲覧可。変更・削除不可 |
| `offer_events` | 表示・詳細表示・見送りの記録。自店の店舗担当者が閲覧可 |

| DB関数 | 用途 |
| --- | --- |
| `app_get_cart(visit_id)`（変更） | 従来の内容に、明細ごとの`discount`・`offerId`・`offerKind`、`discountTotal`、`claimedOfferIds`を追加。既存の項目は変更しない |
| `app_list_offers(visit_id)` | 来店店舗で現在有効・未受け取りのお得と、商品・きっかけ商品・かご内の有無、次に一覧が変わる時刻`nextChangeAt`を返す |
| `app_claim_offer(visit_id, request_id, offer_id, expected_cart_version)` | 受け取り。不足商品の追加・受け取り・かごの版+1・かごイベント（`payload.offer_id`）を一体で保存。同じ要求IDの再送は再適用しない |
| `app_record_offer_event(visit_id, event_id, offer_id, event_type)` | `offer_shown` / `offer_opened` / `offer_dismissed`を1回だけ記録 |
| `kago_checkout`（変更） | 引数・ロック・エラーは#76と同じ。期待総額は割引後。注文明細は定価のまま保存し、割引を`order_discounts`へ保存する（注文総額＝明細合計−割引） |

エラー：`P0001`の`offer_unavailable`（期間外・停止・他店・販売停止）、`offer_claimed`、`trigger_missing`、`visit_ended`。版違いは`40001 cart_changed`。

Appの窓口：

- `GET /api/offers`：上記の一覧をAPP-04のルールで並べ替え、タイムセール・セット割（最大2件）・ゲリラクーポン（1件）を返す。
- `POST /api/offers`：表示・詳細表示・見送りの記録。
- `POST /api/cart`の`action: "claim"`：受け取り。かごの変更と同じく、通信断時は同じ要求IDで再試行する。

注文の集計（DB-09の`kago_order_totals`、INS-08の`kago_product_sales`）は注文明細の定価で集計しており、割引前の金額です。割引後の売上が必要な場合は`order_discounts`を差し引きます。

## 画面

- スキャン欄の下に「いまだけのお得」を表示。タイムセールは開始・終了時刻（日本時間）、定価と割引後価格、「セール価格でかごに追加」。セット割は2商品と1セットあたりの割引額、「セットでかごに追加」。
- ゲリラクーポンは画面右下のステッカー。タップで詳細（商品・割引後価格・関連の理由・期限）を開き、「割引付きでかごに追加」または「今回は見送る」。
- かごは明細ごとに種類と割引額、定価との差、小計・割引・合計を表示する。購入履歴（APP-03）では割引があった注文に割引額を表示する。
- かごが変わったとき、受け取りが拒否されたとき、次のお得の開始・終了時刻、少なくとも1分ごとに一覧を更新する。
