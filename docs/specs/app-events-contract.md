# APP-07: Appの実表示・操作イベント

作業フェーズ: hackday。対象: [Issue #23](https://github.com/jphacks/hs_2604/issues/23)。

`POST /api/events` は共通仕様8.1の形式で `recommendation_impression`、`recommendation_click`、`product_compared` を受け取る。本人の認証セッションでDBへ追記し、利用者・来店・店舗・商品・提案枠を照合する。`received_at` はDBが付与し、種別・広告主・販促版は選定枠から参照する。service roleは使用しない。終了済みの本人の来店への遅延送信も受け付け、DB-06の発生時刻制限を適用する。

実表示は、カルーセルの現在のカードの面積50%以上が連続1秒見えたときに発生する。IntersectionObserverで画面・カルーセルのクリップを判定し、50%未満・非表示タブ・詳細やかごのダイアログ表示・スライド切替で計時をリセットする。候補を取得しただけでは記録しない。同じ選定枠はDBの一意制約と既存トリガーで1件まで。再描画・再表示・再読込も追加計上しない。

詳細を開く操作は `target=detail`、カードと詳細の追加ボタンは `target=add_button` のクリック1件を送る。1秒未満で押してもクリックは記録し、実表示を補完しない。追加は既存の `app_set_cart_item` へ `source=recommendation` と `selectionItemId` を渡す。保存成功時にかご更新とイベントが同時に確定する。失敗時はクリックのみ残る。かご画面の数量変更・削除は従来どおり `source=manual` で保存し、来店・商品・発生順で提案後の削除を追える。

スキャン・手動の商品特定・読み取り失敗は既存の `app_lookup_product`、かごの追加・数量変更・削除は `app_set_cart_item` が記録する。APP-07から重ねて送らない。購入は注文・明細の正本を使う。比較の共通形式は受け付けるが、比較UIの追加・接続はAPP-11の範囲。

送信前に元のUUID・発生時刻・利用者・店舗・来店・提案枠・payloadを利用者別のsessionStorageへ保存し、成功応答後に除去する。再読込や同じタブの来店切替後も元の来店へ再送する。別の利用者のキューは送らない。通信失敗・401・429・サーバーエラーは保留し、10秒間隔、オンライン復帰、タブ復帰で再試行する。400/403/409/422は終端として除去し、後続を止めない。重複排除は既存DB-05のevent_id照合と実表示の枠単位制約による。書き込み後に応答だけ失われても同じ内容で再送する。

イベント送信は買い物の可否に影響させない。ストレージ無効・容量不足の場合はメモリで再送し、その状態での再読込・タブ終了をまたぐ保持は保証しない。sessionStorageのためタブを閉じた後の未送信記録は保持しない。

確認: `pnpm test:events`、`pnpm test:events:e2e`。ローカルのテスト用Auth/HTTPアダプターと、正式な全マイグレーション・RLSを適用した使い捨てPGliteで検証する。共有Supabaseへの書き込み・実機カメラはこの検証に含まない。
