# APP-02：店舗別の商品検索とかご更新

対象：[APP-02 / #18](https://github.com/jphacks/hs_2604/issues/18)。作業フェーズ：hackday。

## 実装方針

- APP-01で確定した本人・店舗・進行中の来店を使用する。既存のZXingスキャナと手動商品選択を接続する。
- 商品名・価格・取扱状態はDBの `products` / `store_products` から取得する。固定のデモ商品を購入対象として扱わない。
- DB-06の直接書込み禁止を維持し、認証済み本人の進行中の来店に限定したDB関数でかごを更新する。
- 数量は更新後の絶対値と読み込んだ `cart_version` を送信する。来店をロックし、古い版による上書きを拒否する。
- 同じ操作の再送には同じ要求UUIDと内容を使用する。DBに保存する要求記録で重複適用を防ぎ、更新・版の増分・イベントを同じトランザクションで保存する。
- 読取失敗・未登録・取扱停止はかごを変更しない。通信失敗時は結果が未確定の操作を保持し、同じ要求で再試行する。
- かご明細と版を一体で取得する。別ブラウザでもログイン・来店選択後に同じDBのかごを復元する。

推薦の再選定はAPP-08、購入確定はAPP-09。公開Vercelの接続設定と新migrationの適用は、ローカル検証・コードのマージとは別に確認する。

## 検証予定

正式DB-06を適用したSQL統合試験で、店舗別価格、本人／他人の権限、追加・数量変更・削除、版競合、再送・要求ID使い回し、イベント原子性を確認する。実ブラウザでは既存スキャナ、コード入力、コードなし商品の手動選択、通信断後の同一要求再試行、別ブラウザ復元を確認する。実行結果・未確認の公開環境はPRに記録する。
