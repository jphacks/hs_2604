# Ads入口の大小文字の正規化（#213）

公開入口の /Ads では、ブラウザ側のpathnameが大文字のままになり、ログイン後の画面分岐が「DB接続の準備中」となる。公開プロキシとAds単独の両方で、元のURLと比較して違う場合だけ /ads へ307転送する。

先頭のAdsサービス名だけを小文字にする。深いパス・リソースID・クエリ・AppやInsightの経路は変えない。既に正しい /ads は転送しない。AdsのリクエストでAppのセッション更新は呼ばない。

## 確認（2026-10-26）

- 公開プロキシ・Ads単独の本番ビルドで44項目成功。
- 大小文字3種類・既存の下位経路・日本語/スラッシュ/重複パラメータ・末尾スラッシュの転送とループなし。
- 未ログイン・メーカー・店舗担当で、ログイン・ホーム・再読込・既存の募集経路・ログアウトを確認。
- App・Insightの独立したCookieは保持。
- パス変換の単体テスト2件、両アプリの型・lint・本番ビルドを確認。
- Auth通信はfixture、SQL/RLSは使い捨てPGliteの正式migration。共有Supabaseのデータは変更しない。
- 公開Vercel上の実ログインは未確認。
