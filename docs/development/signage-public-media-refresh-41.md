# SIG-03（#41）公開画像を通信復帰後に更新する

## 問題
SignageのService Workerは/ad-assets/をキャッシュ優先で返していた。同じURLの素材を更新してもネットワークを見ず、古い内容を返し続ける。

## 修正
公開素材もネットワーク優先で取得し、成功時に保存する。通信失敗時は最後に保存した応答を返す。API・他origin・Range・GET以外の除外範囲、素材期限や認可の判定は既存のまま。

## 確認
- 追加した2件の再現テストが修正前に失敗し、修正後は成功。
- 正式migrationを使うDB試験を含む通常169テスト成功。本番ビルドの型検査とlintも成功。
- モック端末の本番ブラウザ11項目成功。公開URLに専用の一時テキスト素材を用意し、初版取得→同じURLの内容更新→最新版取得→Nextサーバー停止→完全通信断で再読込→保存した最新版の取得を確認。JS/CSS・素材キャッシュ維持と画像デコードも確認。
- 試験用ファイルは終了時に削除。共有Supabaseの変更・カメラ撮影はない。

再現：kago-os/kago-adsで NEXT_PUBLIC_ADS_DATA_SOURCE=mock pnpm build の後、pnpm test:signage:shell:e2e を実行する。テストは直前にビルドした仮データモードを使用するため、DB接続版のビルドを使い回さない。

2026-10-26。実際の会場ネットワーク・端末での確認は別途必要。
