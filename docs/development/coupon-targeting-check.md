# クーポン配布ロジックの動作確認（DEMO-02）

同じ商品をかごへ入れても、利用者ごとに違うクーポンが出ることを確認する手順。仕様は[app-coupon-targeting.md](../specs/app-coupon-targeting.md)。

## 1. 自動テスト（ローカル）

`kago-os/kago-app`で実行する（Node.js 22）。

```bash
pnpm test:offers        # 3人の期待結果・除外条件・履歴OFFなど（31件）
pnpm test:offers:e2e    # ブラウザでのクーポン表示・受け取り・見送り（9件）
```

## 2. 実画面での確認

### 前提

- 共有Supabase（kago-os-dev）に、DEMO-05のseedとmigration `20261025090000`が適用済み（2026-10-24適用）。
- デモ直前に[デモ直前の初期化](demo-reset.md)を行い、3人のかごを空にする。前回の来店で受け取ったり見送ったりしたクーポンは、新しい来店には引き継がれない。
- Appはデモ自動ログイン（[app-demo-session.md](app-demo-session.md)）で開き、ヘッダーでU1〜U3を切り替える。

### 手順

1. 利用者を切り替える。
2. 商品コード`2900000000100`（スパゲッティ 500g）をかごへ入れる。
3. 右下に出るゲリラクーポンのステッカーを確認し、タップして理由を読む。
4. 残りの2人でも1〜3を繰り返す。

### 期待結果

| 利用者 | 出るクーポン | 理由文に含まれる内容 |
| --- | --- | --- |
| U2 田中（履歴OFF） | 生バジル 25%OFF | KAGOが登録した組み合わせ。購入履歴には触れない |
| U1 佐藤 | 新鮮たまご 20%OFF | 公開購買データ、以前購入したことがある、定期購入品は候補から外した |
| U3 鈴木 | トマトパスタソース 15%OFF | KAGOが登録した組み合わせ、まだ購入したことがない |

### 追加で見るとよい点

- 「今回は見送る」を押すと、再読み込みしてもその来店では同じクーポンが出ない。
- クーポンを受け取ると、かごにその商品が割引付きで入る。
- 値引き率が変わると結果も変わる（例：ソースが30%なら田中さんもソースになる）。クーポンの条件は作成後に変更できないため、店舗側で停止して新しい率のクーポンを作る。

## 3. 期待どおりにならないとき

| 症状 | 確認すること |
| --- | --- |
| 佐藤さんに生バジルが出る | 来店の開始が2026-10-24 12:00より前（3回目の購入より前）。初期化して新しい来店にする |
| 佐藤さんに何も出ない | 最後に卵を買ってから18日以内に開始した来店（10/21より前）か、生バジル・ソースの定期判定期限（11/3）を過ぎている |
| 誰にもクーポンが出ない | DEMO-05のクーポンの期間（〜11/7）と`status`、かごに既に候補商品が入っていないか |
| 3人とも同じになる | migration `20261025090000`の適用、田中さんの履歴設定がOFFのままか |

結果の内訳（スコア・関連の出所・新しさの区分）は、`GET /api/offers`の応答の`coupon.targeting`で確認できる。
