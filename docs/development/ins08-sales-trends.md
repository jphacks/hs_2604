# INS-08（#83）販促商品の販売推移

作業フェーズ：通常保守。PR #253。共有Supabaseへの書込・migration追加はない。

## 画面と読取契約

Insightの「販売推移」(/sales)で自店の販促版、開始日・終了日、日本時間の日別/時間帯別、記録の種類を選ぶ。販売数（商品の点数）と販売金額をグラフ・集計表で確認する。停止済みの販促版も振り返れる。従来の販促設定画面は有効版だけを取得する動作を保つ。

認証から得た店舗と、サーバーで取得した自店の販促の商品IDだけを kago_product_sales へ渡す。URLの販促版を直接DBの商品条件へ転用しない。他店の版は選べず、DB関数も他店担当・メーカーを拒否する。ユーザー・来店・注文の個別IDは取得しない。

RPCの契約は [product-sales.md](product-sales.md)。通常操作（疑似購入を含む）・事前投入・合成データを合算しない。金額は注文明細の販売金額であり、利益や販促の因果効果ではない。広告や推薦を経由しない販売も含む。

1回1000行、最大10000行まで安定した区間・由来順に取得する。通信失敗、権限エラー、取得上限を超えた場合は販売0とせず、結果を表示しない。

## 期間と比較の計算

入力日付は日本時間。終了日は含み、実際の集計は [開始, 終了)。販促版の開始・終了と現在時刻の交差で絞り、最大31日。直前期間は実施期間の開始で終わり、経過時間が完全に同じになる。途中時刻の開始/終了も丸めず、比較に使った両期間を秒まで画面に表示する。

販売数はquantity、金額はamountを集計する。無料の販売は金額0でも観測あり。記録がない区間はnullとして線を切り、未確認の空区間を0埋めしない。表でも「記録なし（0とは限りません）」と示す。

記録範囲が確認できた両期間だけ増減と割合を出す。比較元0の場合は増減数を出しても割合は「算出できません（比較元が0）」。前後の比較であり、販促が原因とは言えない旨を数値と同じ枠に示す。

## 記録範囲の設定

現行DBに「無欠落で記録できていた範囲」の正本はない。最初の注文、店舗作成日、販促作成日を記録開始と推定しない。共有環境では範囲を未確認として、観測値のみ表示し「比較できません」とする。空配列が返っても販売0とは断定しない。

別途、記録の運用と無欠落を確認できた場合に限り、Insightサーバー環境変数 KAGO_SALES_RECORDING_COVERAGE に次の構造のJSON配列を設定する。ブラウザ用のNEXT_PUBLIC設定ではない。

    [
      {
        "store_id": "<確認した店舗UUID>",
        "data_origin": "operated",
        "start": "<記録範囲の開始ISO日時・タイムゾーン付き>",
        "end": "<記録範囲の終了ISO日時・タイムゾーン付き>",
        "product_ids": ["<範囲を確認した商品UUID>"]
      }
    ]

product_idsを省略するとその店舗・由来の全商品を保証するため、全商品の無欠落を確認した場合だけ省略する。店舗・商品・由来・両期間全体の一致が必要。不正JSON・逆転日時などは比較を無効にし、設定確認を案内する。接続情報.txtへ説明や仮の保証値は追加していない。

## 固定例と実接続の確認

- 計算12件：JSTの1日/途中時刻、直前の同じ長さ、不正日付/逆転/31日超、未記録と確認済み0、無料販売、由来分離、欠落区間、危険な数値と総額の桁あふれ、範囲の店舗/商品/由来/期間照合、比較元0/増減。
- 本番ビルドした画面6項目：固定例の数量6/3・金額600/300・+100%、時間帯切替、未記録を0%にしない390px表示、実APIの通常操作の販売と他店/メーカー拒否、T1本人ログインの販売画面、T2による他店版の選択拒否。
- 実接続の本人確認はT1/T2/M1。既存注文・販促を読むだけで、検証用販売や素材を追加しない。デモ用自動ログインも使わない。
- ログイン/デモの戻り先に販売推移を加えた。既存のログイン・期間・通常再生履歴の回帰試験も確認。
- 固定例だけの画像：[PC](../images/ins08-sales-mock.png)、[390px](../images/ins08-sales-mobile.png)。共有DBの実績画像・顔画像ではない。

実接続試験はInsightをmockとsupabaseで順に本番ビルドし、ローカル3298ポートで確認する。公開・Vercelデプロイはしない。証拠画像はmockだけを保存し、キー・パスワード・cookieは保存/表示しない。

## 残る運用上の条件

実データでの増減表示には、実際に記録が無欠落である範囲の確認が必要。今回それを未確認のまま比較可能へ切り替えてはいない。販促の因果効果、天候や季節差の統制、販売経路の切り分けはこのIssueの範囲外。
