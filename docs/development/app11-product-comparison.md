# APP-11（#27）商品比較の操作記録

通常保守。商品一覧から2〜4商品を選び、比較画面に商品名・店舗価格・カテゴリ・コードを並べる。商品選択だけを比較とは数えず、2商品以上を並べた表示1回でproduct_comparedを送る。表示し直す操作は新しい比較、通信の再送は同じevent_idと発生時刻を保つ。

購入前の必須操作にはしない。比較しない購入を離脱と分類しない。本人・来店・店舗・商品との対応は既存イベントAPIとDB権限で確認する。再送、表示の再描画、未比較の買い物、他人の来店・他店商品拒否を検証予定。

## 実装・確認結果

商品一覧で2〜4点を選択し「選んだ商品を比較」を開く。選択だけでは送信せず、比較表が表示されたときに一度送信する。非表示のタブで開いた場合は可視になるまで記録しない。再描画では増やさず、戻って開き直す明示操作は新しい比較。来店切替で選択状態は破棄する。

既存EventOutboxを使い、失われた応答や再読込後の再送でも元event_idとoccurred_atを保つ。表は商品名・店舗の表示価格・カテゴリ・コード。商品ごとの単位量は保持していないため単価換算や優劣の推定は行わない。追加は既存のスキャン確認を経由する。

DB付きブラウザ6項目成功：
1. 1商品では開けず、2商品以上で比較できる。選択だけでは比較0件。
2. 2商品・本人来店・元時刻が保存され、再描画では1件。
3. 実SQLへの保存後にHTTP応答だけを失い、元IDで再送しても1件。
4. 開き直しは別件、選択解除、4商品上限。
5. 他人の来店、店舗に存在しない商品をAPI/DBで拒否。390pxのページ横はみ出しなし。
6. 比較を使わない別の来店でも購入画面から注文1件を確定でき、比較0件のまま。かご追加の準備はAPI、確定はUIで実施。

既存イベント7テスト、型検査、lint、本番ビルド成功。試験は使い捨てPGliteへ正規migration/RLS/RPCを適用し、Auth/PostgRESTのHTTP部分だけをテスト用に置き換える。共有Supabaseへの比較データ書込や実スマホ・カメラは含めない。
