# デモ直前の初期化（DEMO-11 #121）

対象は **kago-os-dev** のDATA-01 S1とU1〜U3だけ。DEMO-05のseed適用後、OwnerのSQL Editorで実行する。

1. 接続先がkago-os-devであることを確認する。一般の利用者や本番データには使わない。
2. `select set_config('kago.demo_reset','DEMO-11',false);` を実行する。
3. 同じSQLセッションで `kago-os/kago-core/supabase/demo/reset_demo_visits.sql` を実行する。SQL Editorの接続が切り替わる場合は、2のSQLとファイルの内容を一緒に実行する。
4. 結果が3人それぞれ`active_visits=1`であることを確認する。
5. デモ画面を再読み込みし、既存来店Cookieから店舗選択へ戻る場合は、同じデモ店舗の「続きから開く」で新しい来店へ接続する。DEMO-04の自動接続側も開始／再開した新来店を使う。

旧来店を終了し、空のかごの新来店を作る。クーポンの受取・見送り・表示は旧来店に残り、新来店には引き継がれない。過去の購入履歴、値引き率、旧デモの証跡、他店舗・他利用者のデータは削除・変更しない。
初期化を2回行っても有効な来店は各1件。初期化のたびに新しい来店になり、過去の来店の行数は増える。実行後は確認フラグが解除されるので、再実行時には手順2をもう一度実行する。

APP-13の割引率をseedで元に戻す処理は含めない。値引き率の変更・停止は店舗担当者の判断として残す。履歴の過去日時と割引の有効期間も更新しない。

確認は新来店の`app_get_cart`（かご0件）、`app_list_offers`（claimなし・dismissなし）を利用者権限で行う。既存ログインからのリアルタイム切替や実画面での再配布はDEMO-04／DEMO-02との統合確認が必要。
