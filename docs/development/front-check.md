# フロントの動作確認（App・Insight）

デモ前に、画面の機能が一通り動くかを確認する手順。PRごとの確認ルールは[CONTRIBUTING.md](../../CONTRIBUTING.md)の「8. Vercelのデプロイ制限中の運用」に従う。

## 1. 起動

```bash
cd kago-os/kago-app && pnpm dev          # App: http://localhost:3000/App
cd kago-os/kago-insight && pnpm dev      # Insight: http://localhost:3002
```

共有Supabaseの接続値は`.env.local`へ設定する（[backend.md](backend.md)）。デモ自動ログインを使う場合は[app-demo-session.md](app-demo-session.md)、デモ直前は[demo-reset.md](demo-reset.md)で3人のかごを空にする。

## 2. 自動テスト（App、`kago-os/kago-app`）

変更した機能に関係するものを実行する。ブラウザ確認（`:e2e`）はChromeが必要（`PLAYWRIGHT_EXECUTABLE_PATH`）。

| 機能 | コマンド |
| --- | --- |
| ログイン・店舗／来店選択 | `pnpm test:shopping`、`pnpm test:shopping:e2e`、`pnpm test:session:e2e` |
| スキャン・かご | `pnpm test:cart`、`pnpm test:cart:e2e` |
| 商品から選ぶ（ジャンル） | `pnpm test:menu`、`pnpm test:menu:e2e` |
| 購入履歴・利用設定 | `pnpm test:account`、`pnpm test:account:e2e` |
| おすすめ（選定・カード） | `pnpm test:selection`、`pnpm test:selection:e2e`、`pnpm test:suggestions:e2e` |
| お得情報・クーポン配布 | `pnpm test:offers`、`pnpm test:offers:e2e`、`pnpm test:coupon-open:e2e`、`pnpm test:coupon-redemption:e2e` |
| 操作の記録 | `pnpm test:events`、`pnpm test:events:e2e` |
| 共通 | `pnpm lint`、`pnpm exec tsc --noEmit`、`pnpm build` |

## 3. 画面での確認（App）

スマホ幅（390px程度）で確認する。

| 機能 | 操作 | 期待結果 |
| --- | --- | --- |
| ログイン・来店 | ログイン →店舗を選ぶ（デモ自動ログインならヘッダーでU1〜U3を切替） | 店舗名とかごが表示される。1分ごとの再確認で画面が白くならない |
| スキャン | 「広島デモ店」を選び、商品コード`2900000000100`を入力して「コードで追加」（カメラ、または`/App/demo-barcodes`のバーコードでも可） | 「かごを保存しました。」と出て、かごに入る。他の検証店舗は登録商品が異なる |
| かご | かごを開き、数量変更・削除 | 合計が変わり、再読み込み後も残る |
| 商品から選ぶ | 野菜・肉・魚をタップ | 選んだジャンルの商品が3列で出て「追加」でかごに入る。野菜・肉・魚以外の商品は出ない（コード入力では追加できる） |
| おすすめ | かごに商品を入れる | 縦スライドのおすすめカードが自動で切り替わる。タップで詳細、かごへ追加できる |
| お得情報 | スキャン欄の下・右下を見る | タイムセール・セット割、右下にゲリラクーポンのステッカー |
| クーポン | ステッカーをタップ → 対象商品のバーコードをスキャン、または表示された商品コードを入力して「商品を確認」→「割引付きでかごに追加」 | 確認だけではかごに入らず、追加ボタンで割引付きで入る。対象外のコードは拒否する。一度開いたステッカーは閉じても再表示しない |
| 購入履歴・設定 | 右上の「人」（マイページ）→履歴・利用設定 | 過去の注文が出る。設定を切り替えると保存される |

### クーポンが人によって変わること

デモ用のバーコードはログインなしで`http://localhost:3000/App/demo-barcodes`を開ける。別端末に表示するか印刷する。パスタ・卵・トマトパスタソース・生バジルへのリンクと、17件の読取セルフチェックがある。手入力する場合は、クーポン内の対象商品コードを使う。

デモ直前の初期化後、U1〜U3それぞれでスパゲッティ（`2900000000100`）をかごへ入れる。

| 利用者 | 出るクーポン | 理由文 |
| --- | --- | --- |
| U2 田中（履歴OFF） | 生バジル 25%OFF | KAGOが登録した組み合わせ。購入履歴には触れない |
| U1 佐藤 | 新鮮たまご 20%OFF | 公開購買データ・以前購入した・定期購入品は除外 |
| U3 鈴木 | トマトパスタソース 15%OFF | KAGOが登録した組み合わせ・まだ購入したことがない |

計算の根拠は[app-coupon-targeting.md](../specs/app-coupon-targeting.md)。

## 4. 画面での確認（Insight）

店舗担当者でログインし、各画面が開いてエラーが残らないことを確認する。

| 画面 | 確認すること |
| --- | --- |
| `/promotions` 販促設定 | 対象商品・値引き率を入力・保存できる |
| `/coupons` クーポンの効果 | 一覧と効果が表示される |
| `/metrics` 成果 | グラフが表示される（サンプルデータの場合はその旨の表示） |
| `/review` 広告審査 | 一覧が表示される |

## 5. 期待どおりにならないとき

| 症状 | 確認すること |
| --- | --- |
| 「接続設定がありません」と出る | `.env.local`の接続値 |
| 佐藤さんに生バジルが出る | 来店の開始が2026-10-24 12:00より前。初期化して新しい来店にする |
| 佐藤さんに何も出ない | 来店が10/21より前、または11/3を過ぎて定期判定が変わった |
| 誰にもクーポンが出ない | DEMO-05のクーポン期間（〜11/7）・停止の有無、候補商品がすでにかごにないか |
| 3人とも同じクーポンになる | migration `20261025090000`の適用、田中さんの履歴設定がOFFのままか |

クーポン選定の内訳（スコア・関連の出所・新しさ）は、`GET /api/offers`の応答の`coupon.targeting`で確認できる。

## 6. 疑似購入を通して確認する（APP-09）

1. 商品をかごに追加し、必要ならクーポン・セット割を受け取る。
2. かごの「疑似購入の確認へ」を開き、明細・割引と合計がかごと一致することを確認する。
3. 「この内容で疑似購入を確定」を押し、完了画面に注文番号・購入明細が出ることを確認する。実決済は発生しない。
4. 完了画面を再読込し、同じ注文が表示されることを確認する。
5. 「次の買い物へ」で新しい来店を開始し、マイページの購入履歴に反映されることを確認する。デモモードは来店を自動開始する。履歴利用がONなら推薦入力にも含まれる。

これは共有DBの注文を追加して来店を終了する操作なので、対象のデモ利用者・かごを確認して行う。ローカルの自動検証は `pnpm test:checkout`・`pnpm test:checkout:e2e`。通信失敗・再送・価格変更などの契約とローカル検証範囲は[APP-09](../specs/app-checkout-contract.md)を参照。
