# Appのデモ自動ログイン（DEMO-04）

Appサーバーに `.env.example` の `KAGO_DEMO_*` を設定します。パスワードは非公開ファイルまたはホスティングのサーバー環境変数へ入力し、Git・Issue・PRへ記載しません。`NEXT_PUBLIC_` を付けません。

`KAGO_DEMO_ENABLED=1`、対象店舗のUUID、U1〜U3全員のメール・パスワードが揃うと有効です。登録済みの架空デモアカウントだけを許可します。不完全な設定では有効になりません。通常運用はフラグを `0` にします。

Appを開くとU1としてサーバーでサインインし、対象店舗の来店を再開します。ヘッダーでU1〜U3を切り替えると、かご・履歴・推薦の取得に使う本人が変わります。ブラウザには利用者の記号と来店IDのみをHttpOnly Cookieで保存します。Supabaseの認証トークンはサーバーメモリだけで保持します。

デモモードでは訪問者が3人の架空アカウントを自由に選択できます。公開対象と利用期間を限定したデモ環境に設定してください。同じ利用者を選んだ端末は同じ本人の来店を共有します。

認証失敗は接続エラーとして扱い、入力値やAuthのエラー詳細を返しません。デモモードの通常ログイン・ログアウト・任意店舗への移動は拒否します。U1〜U3のサーバーセッションは最大5分キャッシュし、設定変更時と認証失敗時は破棄します。

## 担当範囲

この実装はApp側です。Insightの店舗担当者サインインは #125 の担当実装と接続します。クーポン選定 #116 は別実装であり、3人別のクーポン選定完了を意味しません。

## 確認

- `node --experimental-strip-types --test tests/demo-config.test.mts`
- `PLAYWRIGHT_EXECUTABLE_PATH=/path/to/chrome node tests/demo-session.e2e.mjs`
- `node tests/shopping.e2e.mjs`（デモ無効時の回帰確認）

E2Eの認証情報はテスト用HTTPフィクスチャだけに使用します。実DB検証用の認証情報はテストファイルに保存しません。
