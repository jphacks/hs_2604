# DEMO-10・DEMO-06：App UI

対象：DEMO-10（#120）、クーポン部分はDEMO-06（#117）。PR #140でまとめて確認する。共有のホーム・ダイアログ・かごを使うため、今回のクーポンUIも同じPRに含めた。

## 実画面
- `/App`：固定ホーム、同じ枠に切り替わるカメラ、4カテゴリ、保存済みの広告・おすすめ、買い物かご。広告枠は5秒間隔・上下スワイプ・スクロールで切り替え、動きを減らす設定に従う。
- `/App/history`：本人の購入履歴、すべての店舗／店舗別、期間、詳細の展開。
- `/App/account`：設定の保存、ホームのかごを開く導線、店舗・来店選択、ログアウト。
- 認証・接続エラー・店舗QR・商品詳細・クーポン・`/App/checkout`の確認／完了にも反映。
- `/App/store`はAppロゴを使わず **KAGO/Store** 表記。サービスの所属整理は個人の確認タスクとし、権限や管理機能は拡張しない。
- `/App/demo-barcodes`：既存の印刷用コードを維持し、画面だけ統一。印刷時は装飾を隠す。

画面で商品やクーポンを選ぶだけでは商品を追加しない。対象のバーコードを照合してから既存の追加・割引処理へ進む。カメラが使えない場合はバーコード番号を入力する。購入は既存のデモ注文処理で、実決済は発生しない。

ホームと店舗選択はページ自体をスクロールさせない。明細など長い内容は専用領域をスクロールする。Appロゴの寸法・位置は共通ヘッダーで揃える。

## 検証（2026-10-25）
- `pnpm test:ui:e2e`：12項目。5画面サイズ、カタログとコード照合、設定、かご導線、店舗別履歴、他人の履歴の排除、クーポン、注文保存と二重注文防止、Store表記、印刷用コード、削除確認。
- ZXingの読み取りは合成バーコード映像を使用。顔や実カメラの映像は取得していない。
- `pnpm test:coupon-open:e2e`：既存の7項目。開封後の非表示、閉じる・Escape・背景、来店変更、別ユーザー、割引保存、表示設定の保存失敗。
- 関連する10個のテストコマンド、計127件成功：account／cart／offers／selection／checkout／events／refresh／coupon-appearance／menu／suggestions:new。
- lint、Next.jsの型生成、TypeScript、本番webpackビルド成功。
- 公式migration・RLSを読み込んだ一時PGliteと架空認証で検証。共有Supabase・実スマートフォン・実カメラの確認結果ではない。
- クーポンのローカル表示時間は、かご保存の確認から263ms（測定例）。実機での1秒条件は未確認。

画面幅：390×844、375×667、320×568、430×932、1280×900。実機条件が残るためIssueを閉じず、PRはDraftで確認待ちにする。旧UIを前提とする個別E2Eすべての成功は主張しない。今回の操作経路は上の統合テストで確認する。

## ローカル表示
Appで `pnpm preview:shopping` を起動し、`http://localhost:3210/App` を開く。既存の確認用ログインは架空データ専用。共有Supabaseには接続せず、終了すると変更は消える。`/ui-preview/*` は開発時だけの比較用で、実機能は上の実画面を確認する。

## 素材
ロゴ・商品画像は既存素材。`public/images/shopping/` のfresh-family、scan-scene、category-fruit／vegetables／breadは、この作業で内蔵imagegenから生成・編集した写真。文字・ロゴ・UIは含めず、HTMLで重ねる。スキャン写真は右側に手とスマートフォン、左に説明用余白。カテゴリは白背景の食品写真。端末の時刻・電波・電池は描かない。
