# INS-07（#82）店舗セッションの実接続確認

2026-10-27、通常保守、main 62d9493。共有SupabaseとInsight本番ビルドで8項目が成功した。DB・認証の実装変更、業務データ書込、カメラ・撮影・録画は行っていない。

- 未ログインで審査・販促・成果の3画面を開くとログインへ戻り、店舗情報を表示しない。
- T1でログインすると所属店舗の名前を表示し、再読込しても保持。
- T1の3画面で同じ店舗名を確認。
- 実際にログアウトし、3画面への再アクセスを拒否。
- 同じブラウザでT2へ切り替えると、T2の正しい店舗名だけを表示。
- T2の再読込でも保持。
- 認証Cookieを無効な値へ置換すると、3画面を拒否。
- M1のメーカー権限では店舗Insightへ入れず、役割エラーを表示。

認証Cookieのケースは壊れた認証状態の拒否確認であり、実時間のJWT期限経過を待った試験ではない。所属がないstore_staffは検証アカウントに存在せず、今回その実接続ケースは作っていない。

途中の試験ではリダイレクト完了前のURL判定と、別店舗名に一部含まれる文字列の判定が合わなかった。完了待ちと店舗名の完全一致へ修正し、全体を再実行して成功。製品側の店舗漏洩は再現していない。

## 再実行

非公開の接続ファイルにSupabase URL・publishable key・T1/T2/M1の分類済みアカウントを用意する。接続値や認証Cookieを保存・出力しない。デモの自動ログインは無効にして実行する。

    cd kago-os/kago-insight
    KAGO_STORE_SESSION_LIVE=1 KAGO_CONNECTION_FILE=/path/to/private/connection.txt node --experimental-strip-types tests/store-session.live.e2e.mjs

本番ビルドとローカル3297番サーバーを作成して終了する。ChromeのパスはCHROME_PATHで指定可能。再実行で同じ本番ビルドを使う場合だけKAGO_E2E_SKIP_BUILD=1を指定する。
