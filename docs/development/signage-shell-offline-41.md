# SIG-03（#41）通信断時の画面・素材の再読込

## 修正

- AdsはassetPrefix=/ads-staticで配信する。Workerと初回の事前保存で、/ads-static/_next/static/のJS・CSSも扱う。従来の/_next/static/も保持する。
- Workerのキャッシュ名はkago-signage-shell-v2。更新時に削除するのは旧シェルだけ。kago-signage-media-v1のBlob素材と他サービスのキャッシュは消さない。
- Worker起動前に読み込んだ公開素材も、素材ローダー自身がBlobキャッシュへ保存する。通信断ではここから読み出す。署名付き画像は従来どおり相対パスを鍵にし、署名URLは保存しない。
- WorkerはSignageの画面・静的JS/CSS・公開広告素材だけを扱う。通常Ads・Auth・DB API・他origin・Range・書込みは横取りしない。precacheメッセージも保存対象を制限する。
- キャッシュ保存の完了を待つ。容量不足で保存できなくても、正常なネットワーク応答は返す。
- 表示期限・停止状態・再送の判定は従来のエンジンが担当し、ここでは変更しない。

- Workerの実コードを読み込む5テスト：旧シェルだけの削除、保存対象、現在/旧形式のJS・CSSの通信断、対象外リクエスト、容量不足。
- Adsの通常テスト157件成功。型・lint・本番ビルド成功。
- 模擬端末D1の本番画面で8項目成功。旧シェルと素材キャッシュを事前に作り、更新で素材を消さないこと、JS・CSSの保存、配信サーバー自体を停止した後のService Worker応答・React再起動・素材表示を確認。
- カメラは起動せず、スクリーンショット・映像・顔画像の取得なし。共有DBの変更なし。
- これは模擬端末の画面・素材の回帰検証。実端末アカウント、会場回線、カメラ精度の確認として扱わず、#41全体を閉じない。
