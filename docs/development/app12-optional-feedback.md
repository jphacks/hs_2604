# APP-12（#28）推薦非表示と任意の削除理由

通常保守。APP-11 PR #254の上に分離する。推薦詳細を閉じただけでは拒否とせず、明示的な非表示ボタンを記録する。成功した削除のevent_idへ理由を対応付ける。

削除理由の提示・明示スキップを別イベントとして追加し、本人入力あり／未設定／未収集を区別する。理由の選択は任意。未入力のまま閉じても在庫や心理を推測しない。DB変更は既存イベントとの後方互換性を保ち、正規migration/RLSを用いる使い捨てDBで検証する。

## 実装・共有環境・確認結果

推薦の非表示は本人・来店別のsessionStorageに保存し、ホームとおすすめ一覧で共有する。将来の新しい選定への恒久的な商品拒否とは区別する。

削除の成功後だけ、元の削除要求IDに対応する理由欄を表示する。理由は4選択肢で、自由記述の個人情報は収集しない。未選択では送信せず、入力なしで続ける操作を用意する。提示は欄の25%以上が可視の場合だけ記録。提示し直した場合の複数イベントは、集計では元削除単位でまとめる。

20261027120000_optional_removal_feedback.sqlでprompted/skippedを後方互換で追加。本人・店舗・来店・商品が元削除と一致することをDBでも検証。2026-10-27、TLS証明書と既知の検証店舗を照合して共有Supabaseへ適用し、標準migration履歴にも登録した。新payloadの検証成功。既存イベント・注文は変更していない。共有Auth/APIでの実際の理由入力は今回まだ行っていない。
