## SIG-01〜03（#39〜#41）：通常広告での追加7項目

別の専用募集2件で食パン広告A・Bを作り、同じ本番Signageを通常の承認順モードで実行した。

- 承認した2つの素材版だけを使う検証対象を作成。
- A→Bの順、画像デコード、Aの3秒以上の再生、素材版・schedule・approved_orderを確認。
- Chromiumをofflineにして再読込しても、非公開Storageから事前取得した画像をキャッシュで表示。
- Bの掲載期限を実時間で経過させ、切断中もBを表示し続けず、有効なAを表示。
- 切断中にAを店舗アカウントで停止。端末が停止を即座に知るとは仮定しない。試験ブラウザの保存済みfeed.expires_atだけを過去にして再読込し、cache_expiredの広告なし案内へ切替。
- 復帰後、停止済みA・期限切れBを表示せず、未送信9件を同じID・素材版で保存。再読込後も同じ9件は重複しない。
- ログアウト・再読込後に古い広告を復元しない。

キャッシュ期限のケースは明示的な期限切れデータの注入であり、10分間の実時間待機とは区別する。壁時計・DB時刻・再生時刻は変更していない。人数や視認の測定は行っていない。

## 再実行方法

非公開の接続情報ファイルにSupabase URL・publishable keyとT1/M2/U1/DV1の分類済みアカウントを用意する。値・署名URLをIssue／PRへ転載しない。U1は履歴・現在のかごの利用設定がONで、自店の既存かごが空であることが前提。非空なら試験は開始せず止まる。T1とDV1は同じ店舗、M2は素材のメーカー。

kago-osで依存を用意し、kago-adsから実行する。

    pnpm install --frozen-lockfile
    cd kago-ads
    KAGO_SHARED_LOOP=1 KAGO_CONNECTION_FILE=/path/to/private/connection.txt node --experimental-strip-types tests/shared-loop.live.e2e.mjs
    KAGO_SIG_NORMAL_LIVE=1 KAGO_CONNECTION_FILE=/path/to/private/connection.txt node --experimental-strip-types tests/signage-normal.live.e2e.mjs

ChromiumはCHROME_PATHで指定可能（既定/usr/bin/google-chrome）。最初は3アプリの本番ビルドを作成する。通し試験は3281〜3283番、Signage単独試験は3295番を一時的に使用する。通常のpnpm testでは実行されず、明示フラグと非公開ファイルの指定を必須にする。ビルド再利用時のみKAGO_E2E_SKIP_BUILD=1／KAGO_SIG_SKIP_BUILD=1を指定する。
