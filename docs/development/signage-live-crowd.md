# SIG-06（#44）実店内集計・選定履歴・Insight

## 動作

- 自店端末の通常のユーザーセッションで `kago_signage_crowd()` を呼ぶ。店舗ID・時刻・人数は呼出側から指定しない。
- 自店のactive来店のうち、直近15分に活動があった利用者を重複せず数える。全体が5人未満なら人数は0、カテゴリは空。カテゴリ自体も5人以上の場合だけ返す。
- 配信中のメーカー広告の商品カテゴリに合うかご傾向を返す。同カテゴリ内は数量ではなく、そのカテゴリの商品をかごに持つ利用者数で数える。個人ID・来店ID・かご明細は端末へ渡さない。
- 集計のサーバー時刻と端末時刻の差を配信内容へ反映する。
- 既存の `sig06-crowd-v1` と同じ選定。割合の高い広告、同率なら対象IDの順で決める。集計不足・取得失敗・5分の期限切れ・素材なしでは汎用案内にする。通常の設定順と店舗販促の交互表示は、集計選定を無効にしたときの動作として残す。
- 選定版・重み・集計・理由を再生IDに結び付ける。少人数などの抑制時は集計内訳を保存しない。
- 終了した再生を保存後、`kago_record_signage_decision` で履歴を保存。通信失敗時は同じ再生IDのまま既存の永続キューに残す。再送は同内容なら重複しない。これは2つのAPI呼出しなので途中では再生だけ存在しうるが、履歴保存成功までキューから削除しない。恒久的な制約違反は拒否件数へ加える。
- Insightの「サイネージ選定」で、自店の選定時刻順の直近100件を表示する。理由・対象人数・カテゴリ・選定版・重みを確認できる。「最新の履歴に更新」で再取得する。履歴は端末報告であり、サーバーが独立に購買の原因やカメラ精度を検証した記録ではない。

## 適用と有効化

1. 共有DBの適用履歴を確認後、`20261026010000_signage_crowd_decisions.sql` を適用する。新しい表・関数・索引を追加し、既存業務データは更新しない。APIスキーマ再読み込みを含む。
2. Ads/Signageを `NEXT_PUBLIC_ADS_DATA_SOURCE=supabase`、`NEXT_PUBLIC_SIGNAGE_CROWD_SELECTION=1` でビルドする。
3. 端末アカウントで `/signage/play` を開く。既定は従来の設定順。共有DBの準備前に集計選定を有効にしない。
4. 自店スタッフでInsightの `/signage-decisions`（統合公開では `/insight/signage-decisions`）を開く。

端末のみが集計・履歴追加RPCを使える。停止端末・顧客・メーカー・店舗スタッフにはRPCを許可しない。履歴の直接INSERT/UPDATE/DELETEは一般利用者には許可しない。店舗スタッフには所属店舗のSELECTだけを許可する。

DBでも、再生と選定の端末・店舗・理由・時刻・対象、カテゴリの最小人数、重みの再計算、最大重みの選択、重複・追加フィールドを検証する。理由の自由文は保存せず、管理された説明文に置き換える。
