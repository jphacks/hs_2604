# Insight → Appの店舗おすすめデモ（#170）

値引き・ゲリラクーポンとは別の機能です。Insightで `store_promotions / promotion_versions` に設定し、Appの `store_promo` 枠（「店舗からのおすすめ」）に表示します。既存の保存・候補選定RPCを使用し、DB変更はありません。

## 事前条件

- Insightの担当者とAppの利用者が同じ店舗（広島デモ店）を使う。
- Appのかごに対象商品が入っていない。
- 掲載先にAppを含め、現在が日本時間の有効期間・曜日・時間帯の中である。
- 店舗おすすめ枠は1件だけ。複数設定がある場合は優先度の高いものを選び、同じ優先度ではかごとの関連性などで選ぶ。新しく保存した商品が無条件に最優先になる仕組みではない。

## デモの流れ

1. Insight `/insight/promotions` の「おすすめ」を開く。おすすめの新規追加、または既存設定を編集する。
2. 商品、Appの掲載先、優先度、利用者に見せる理由を入力する。新規設定の初期値は終日・本日から7日後の0時まで。期間の終了日はその日の0時で終了する。
3. 保存し、実DBに保存した版番号と一覧を確認する。再読み込み後も設定が残る。
4. 同じ店舗でApp `/App` を開き、ホームカード下の「おすすめを更新」を押す。かごの追加・削除や購入は不要。
5. カード横のドットから「店舗からのおすすめ」を選ぶ。商品とInsightで入力した理由を示す。詳細画面でも理由を確認できる。
6. Insightで理由を編集して保存し、Appでもう一度「おすすめを更新」を押すと変更が反映される。
7. Insightで停止し、Appを更新すると対象の店舗おすすめが消える。他の有効なおすすめがあればそちらに切り替わる。

商品を変える場合は新しく追加する。既存版の対象商品は変更しない。初めての新規追加・停止済み商品の再設定では既存の販促がDBで解決され、編集では取得した版番号で競合を検査する。失敗した保存では、以前の有効な設定を停止したまま残さない。

## 表示されない場合

店舗、かご内の商品、App掲載先、現在日時、優先度を確認する。カルーセルには広告・値引き・いつもの商品なども並ぶため、「店舗からのおすすめ」のドットで切り替える。通信失敗時はエラーを確認し、再試行する。

保存メッセージで「モックのため保存されません」と表示された環境では、実DBを使うAppに反映されない。Insightの `NEXT_PUBLIC_INSIGHT_DATA_SOURCE` を確認する。

## 検証

Appで `node --experimental-strip-types --test tests/store-promotion-flow.test.mts tests/recommendation-refresh.test.mts tests/selection-service.test.mts`。実際のmigration・RLS・保存関数・App選定を使用し、保存・編集・停止・商品変更・かご内商品の除外・競合と不正入力のロールバック・他店舗拒否を確認する。

公開環境へのコード反映はPRレビュー後。共有開発DBで作成したデモ設定は公開Appでも同じ店舗・同じ条件なら表示対象になるが、既存コードで最新取得するには画面の再読み込みが必要。

## 共有開発DBで用意済みの設定（2026-10-25）

広島デモ店（`hiroshima-demo-store`）に「きゅうり 1本」を第3版・優先度100で設定済み。Appを掲載先に含め、終日、2026-10-25から2026-11-01 00:00 JSTまで有効。理由は「デモ：店舗が設定したきゅうり 1本のおすすめです。」。既存の他商品・クーポン設定は維持している。

共有開発DBにつないだローカルApp/Insightで、新規保存・再読込・理由の変更・停止・再設定とAppへの反映を確認済み。確認前後でかごとその版番号は同じで、購入操作は行っていない。デモ前には対象商品がかごに入っていないことを確認する。
