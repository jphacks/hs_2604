通常保守。PR #90はmainへ反映済み。専用の募集・素材・申請で、却下後の新版再申請と承認、承認後の新版再審査、媒体別画像、旧履歴・旧配信、メーカーの越権拒否を最終照合する。

正式デモカタログの未申請版や既存申請を流用・変更しない。店舗の審査は本人のInsight画面で実施し、登録・版追加・申請は正式データ層を使う。検証後は専用配信だけ停止し、専用募集を終了する。素材・履歴は削除しない。カメラ・実際の決済・Vercel公開は使わない。

## 2026-10-27の結果：実接続5項目成功

1. M1が2媒体の専用素材を登録・申請。審査中の再申請、M2からの他社申請取得、メーカーの直接承認を拒否。
2. T1がInsightの実画面で理由付き却下。M1が別画像の第2版を追加し、同じ申請IDで第2回の申請へ。旧却下理由・旧素材版を保持。
3. M1本人がAdsにログインして再申請後の履歴を表示し、店舗の旧コメントを確認。
4. T1がInsightで第2回を承認し、その版・revision=2に一致する配信対象を作成。
5. M1が承認後に第3版を追加して再申請。次の承認までは第2版の配信がactive。第3回承認後は旧配信がsuperseded、新配信がactive。3素材版・2媒体ずつと、rejected/approved/approvedの履歴を保持。

メーカーの登録・版追加・申請は正式な本人データ層、店舗の却下・承認とメーカーの履歴確認は本番ブラウザ。登録フォーム全操作を今回の実接続で繰り返したものとは区別する。共有Auth/Storage/APIを使用し、管理キーやDB直書きで審査しない。

途中の試験では、ログインフォームが読込中にも消えることを認証完了と取り違えた。実際に認証後のログアウトボタンを待つよう修正。旧版の置換状態をsuspendedと仮定した箇所は正規のsupersededへ照合を修正した。製品の動作不具合とは扱わず、全体を再実行して成功した。

専用募集は終了し、残るactive配信は停止した。途中の試験で作った専用募集も終了済み。試験素材・申請履歴は監査用に保持し、既存の正式デモカタログや元の申請は変更していない。検証中の配信は専用の検証店舗だけ。
