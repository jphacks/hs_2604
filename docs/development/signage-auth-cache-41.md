# SIG-03（#41）認証とキャッシュの境界

## 修正

- 起動時に認証失効が分かった場合も、表示中と同様に保存済みセッション・配信を消す。直後にオフラインで起動しても失効済み配信を復活させない。
- 保存済み配信・取得した配信の端末IDと店舗IDを、端末セッションと照合する。新しい端末へ切り替えた直後に通信が失敗しても、前端末の配信・選定履歴を表示しない。
- 通常の通信断では、同じ端末の有効なキャッシュを引き続き使う。未送信記録は端末ごとに保持し、ログイン中の端末のものだけを送る。
- ログアウト・停止を境に、それ以前の認証/配信の非同期応答を反映しない。古い要求が残っていても新しいログインを妨げない。
- 権限拒否（停止端末など）を通常の通信断と区別し、再ログイン画面へ戻す。
- 壊れた構造の保存配信や記録があっても起動を落とさず、正常な未送信記録は保持する。

## 確認（2026-10-26）

追加11件：認証失効とオフライン再起動、端末切替後の取得失敗、通常オフライン、保存端末の不一致、ログアウト後の認証/配信応答、異なる配信の取得、破損保存、正常記録の保持、古い要求と新しいログインの競合、停止端末のRLS拒否。

通常163テスト、型・lint・本番ビルド成功。停止端末は正式migration・RLSを使う使い捨てPGliteで確認する。共有Supabaseや実機カメラの確認ではない。#41全体の実機確認を完了したものとして扱わない。

PR #217のシェル・素材キャッシュ修正とは独立した変更。未送信記録のIDやDB権限は変えず、共有DBの変更も行わない。
