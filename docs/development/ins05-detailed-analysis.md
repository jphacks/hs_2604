# INS-05（#38）商品・時間帯・推薦手法の詳細分析

通常保守。APP-12 PR #255のDB定義へ依存する。基本成果画面と販促単体の前後比較とは分け、店舗内で何が・いつ売れたか、観測できた表示からの推薦追加、本人の明示操作を確認する。

由来・店舗・期間を固定する。表示記録がある選定商品を追加率の母数とし、未計測の追加は別枠。削除理由は本人入力・明示スキップ・提示後未入力・提示記録なしを元削除単位で区別する。比較しない購入を離脱とせず、無欠落の記録範囲や因果効果を主張しない。

## 画面・集計契約

Insightの「詳細分析」(/analysis)。開始/終了日（日本時間、終了日を含む）、通常操作（疑似購入を含む）/事前投入/合成を選択する。最大31日、現在時刻で絞る。商品ランキングは数量順の上位20商品。時間帯は同じJSTの0〜23時台を期間内で合算し、商品別とは異なる観点で見る。金額は値引き前の注文明細金額。

販売は既存kago_product_salesをhourで安定順に1000件ずつ最大10000件取得する。上限超過や失敗時に販売0へ置き換えない。空の時間帯はnullであり0を保証しない。名称は返された商品だけを100件ずつ解決する。

## 推薦と本人操作

kago_detailed_insightは本人のstore_staff役割とstore_membersを確認し、自店・指定由来・[開始,終了)の集計だけを返す。個別の利用者・来店・イベント・選定商品IDは返さない。

手法別の母数は期間内の表示記録がある選定商品枠数。分子はその表示以降、期間内に推薦から追加した枠数。連続した再追加は同じ枠として1件。表示前、選択期間より前の表示、表示記録なしの追加/非表示は別枠とし、追加率へ混ぜない。購入率・利用者数・因果効果ではない。期末にまだ追加していない枠も、離脱や拒否と断定しない。

比較は記録された比較操作数だけを示す。比較しない購入や比較後未購入を離脱とは扱わない。比較0件でも機能未使用/未収集を区別できる保証はない。

削除理由は期間内に削除したイベントを対象にし、理由は現在までの記録を元削除単位でまとめる。優先順は本人入力→明示スキップ→提示後未入力→提示記録なし。理由の後日入力で過去の削除の状態は変わり得る。提示イベントの重複で削除件数は増えない。本人入力が複数ある旧データは最初の理由を採用する。UIの4選択肢以外の旧自由記述は「その他の入力理由」としてまとめ、原文を返さない。
