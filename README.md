# KAGO/OS

**いつもの買い物にちょうどいい提案を**

![KAGO/OSのコンセプト：スマホで商品をスキャンする買い物客と、販促を管理・分析する店舗スタッフ](docs/images/kago-concept.png)

## デモを体験する

**「お店がおすすめを設定すると、買い物中のスマホに届く」流れを、店舗担当者とお客さんの両方の立場で体験できます。** PCとカメラ付きスマートフォンを1台ずつ用意してください。アプリの開発環境を用意する必要はありません。

| 使う端末 | 開く画面 | 体験してほしいこと |
| --- | --- | --- |
| **PC** | [KAGO/Insight：販促設定](https://kago-os.vercel.app/insight/promotions) | 店舗のおすすめ商品と、伝えたい理由を設定する |
| **スマートフォン** | [KAGO/App](https://kago-os.vercel.app/App) | 商品をスキャンし、おすすめ・クーポンを見ながら買い物して、疑似購入する |
| **PC** | [KAGO/Insight：販促効果](https://kago-os.vercel.app/insight/coupons) | ダッシュボードで結果を振り返り、次の販促を考える（**モックデータ**） |

### はじめに：ログイン情報を受け取る

デモ担当者から、**広島デモ店の店舗担当者用アカウント（Insight用）**と、**お客さん用アカウント（App用）**のメールアドレス・パスワードを非公開で受け取ってください。2つは役割が異なるため、使い分けます。現在、画面からの新規アカウント登録は案内していません。

実際のお金はかかりませんが、疑似購入の履歴は保存され、後の提案に影響します。購入まで試す場合は、担当者から**購入してよい体験用アカウント**を受け取ってください。撮影用の共有アカウントを使う場合は、購入前に担当者へ確認してください。

自動ログインが有効なデモ環境では、ログイン画面を経由せずに開くことがあります。その場合は画面の店舗名・利用者を確認して次へ進みます。ログイン情報はこのREADMEには掲載しません。

### 1．PCで店舗のおすすめを設定する

1. PCで [KAGO/Insightの販促設定](https://kago-os.vercel.app/insight/promotions) を開きます。ログインを求められたら、**店舗担当者用**のメールアドレスとパスワードを入力して「ログイン」を押します。
2. ヘッダーの店舗名が **「広島デモ店」** であることを確認し、「販促設定」→「おすすめ」を開きます。
3. 「おすすめを追加する」または「＋ 販促を追加する」を押します。例として **「きゅうり 1本」** を選び、おすすめの理由に「今日の食卓に、みずみずしいきゅうりを。」など、スマホに表示したい文章を入力します。
4. 掲載先の **「App」** を選び、優先度を **100** にします。時間帯は追加せず「終日」のままにし、有効期間に今日が含まれていることを確認します。
5. 「この内容で追加」を押します。保存完了の表示を確認したら、PCの画面をそのままにして、次はスマホを使います。

同じ商品がすでに設定されている場合は「編集する」から理由などを変更して保存してください。Appには店舗おすすめが1件表示され、複数ある場合は優先度などで選ばれます。体験者同士で同じ店舗を使うため、設定が変わることがあります。

### 2．スマホでAppを開く・ホーム画面に追加する

スマホで [KAGO/App](https://kago-os.vercel.app/App) を開きます。iPhoneはSafari、AndroidはChromeでの利用を案内しています。ブラウザのままでも体験できます。

ホーム画面に追加すると、アイコンからアプリのように起動できます（PWA）。追加は任意です。

| 端末 | ホーム画面への追加方法 |
| --- | --- |
| **iPhone／Safari** | 共有メニュー（四角から上向きの矢印）→「ホーム画面に追加」→「追加」。「Webアプリとして開く」が表示された場合はオンにします。 |
| **Android／Chrome** | 右上の「︙」→「ホーム画面に追加」または「インストールしてショートカットを作成」→「インストール」。画面の案内に沿って進みます。 |

表示名やメニューの場所はOS・ブラウザのバージョンで異なります。見つからない場合は [Appleの案内](https://support.apple.com/ja-jp/guide/iphone/iphea86e5236/ios)・[Googleの案内](https://support.google.com/chrome/answer/9658361?co=GENIE.Platform%3DAndroid&hl=ja)を参照するか、そのままブラウザで続けてください。ホーム画面から開き直した際にログインを求められたら、同じお客さん用アカウントでログインします。体験中はインターネット接続が必要です。

### 3．ログインして「広島デモ店」を選ぶ

1. Appのログイン画面に、**お客さん用**のメールアドレスとパスワードを入力し、「ログイン」を押します。
2. 「お買い物の店舗を選ぶ」画面で、下の「デモ用の店舗を選択」から **「広島デモ店」** を選びます。店舗QRコードが手元にある場合は、QRの読み取りでも入店できます。
3. 「この店舗で買い物を始める」を押します。続きの来店がある場合は「前回の店舗から再開」と表示されます。
4. ホーム上部の「ご利用店舗」が **「広島デモ店」** になっていることを確認します。すでにホームが開いていて店舗を選び直したい場合は、「マイページ」→「店舗・来店を選ぶ」から戻れます。

### 4．商品をスキャンして、提案を見てみる

1. PCで [読み取り用デモバーコード](https://kago-os.vercel.app/App/demo-barcodes) を別タブに開きます。スマホでこのPC画面を読み取ります。印刷したバーコードでも体験できます。
2. スマホのホームで「カメラで読み取る」を押し、カメラの利用を許可します。まず **「スパゲッティ 500g」** のバーコードを枠に合わせてください。読み取りに成功すると、商品がかごに追加されます。
3. ホームのカードを見てください。「あなたへのおすすめ」「店舗からのおすすめ」「広告」などを、カード横の点で切り替えられます。おすすめは、かごの中身・購入履歴・利用設定などによって変わります。
4. **Insightで設定した内容を確かめるには**、「おすすめを更新」を押し、「店舗からのおすすめ」のカードへ切り替えます。先ほど設定したきゅうりと理由が表示されるかを確認し、「詳細を見る」で内容を開きます。
5. 気になったおすすめ商品を買う場合は、詳細の「商品のバーコードを読み取る」から、その商品のデモバーコードを読み取ります。カードを見ただけでは商品はかごに追加されません。
6. クーポンが届いた場合は、画面の案内に沿って受け取り、対象商品のバーコードを読み取って利用を体験してください。利用者や設定によって届くクーポンは異なり、毎回必ず表示されるわけではありません。

**おすすめの追加前・追加後を比べたい場合**は、担当者と一緒に、対象のおすすめが停止している状態でAppを更新 → Insightで追加・保存 → Appを更新、の順に操作してください。保存した商品・理由がスマホに現れることで、2つの画面のつながりがわかります。

対象商品がすでにかごに入っていると、その商品のおすすめは表示されません。きゅうりの表示を確かめてから、その商品をかごに追加してください。

### 5．かごを確認して、疑似購入する

1. ホームの **「買い物かご」** を開き、商品・数量・合計を確認します。不要な商品は削除できます。
2. **「レジに進む」** を押し、商品・割引・お支払い合計を確認します。
3. **「お会計を確定する」** を押します。「お買い物が完了しました」と表示されたら疑似購入は完了です。

**実際の支払い・カード決済は発生しません。** 購入履歴は保存されます。撮影用の「いつもの商品」カードを確認中の場合は、表示条件が変わるため、その対象商品の購入を確定する前に担当者へ確認してください。

### 6．PCに戻って、販促効果のダッシュボードを見る

PCのInsightで **「販促効果」** を開きます。クーポン経由の売上、購入率、配布から購入までの流れ、クーポン別の比較などをグラフで確認できます。下の **「次の打ち手」** では、結果を踏まえて、継続・拡大・見直しを考えるイメージを体験できます。「販促設定へ」から設定画面に戻れます。

**この効果画面はモック（固定のサンプルデータ）です。直前に行ったスキャン・購入や、設定したきゅうりの実績が反映された数値ではありません。** 今回体験できるのは、実際のおすすめ設定とApp表示の連携、および、サンプルを使って結果確認から次の施策へつなげる画面です。

### 困ったときは

| 状況 | 確認すること |
| --- | --- |
| ログインできない／情報がない | Insight用とApp用のアカウントが合っているか確認し、デモ担当者へ連絡してください。 |
| カメラが開かない／読み取れない | Safari・Chromeでカメラを許可してください。商品検索から商品を探す方法や、「バーコードが読み取れないとき」の商品コード入力でも試せます。スパゲッティのコードは `2900000000100` です。 |
| 普段買っている商品のバーコードが見つからない | このデモは登録済みの架空商品を使います。上記のデモバーコードを利用してください。 |
| 設定したおすすめが出ない | 両画面が広島デモ店か、掲載先がAppか、期間が有効か、商品がかごに入っていないかを確認し、「おすすめを更新」を押してください。ほかの有効設定があれば優先度も確認します。 |
| ほかの人の操作で表示やかごが変わる | 同じアカウント・店舗を共有している場合があります。担当者に別の体験用アカウントや体験順を確認してください。 |

## 製品概要

### 背景（製品開発のきっかけ、課題等）

スーパーで置き去りになっている「デジタルサイネージ」みたことありませんか？
店員にとって、チラシやデジタルサイネージで広告を出しても、「お客さんに届いたか」「商品選びにつながったか」が見えにくいことが課題です。
POSの購入結果だけでは、広告に接してから購入するまでの経緯を追いにくく、次の販促を考える材料が限られます。

一方、お客さんはチラシ広告を見なかったり、店内の広告やクーポンに気づかなかったりして、買い物に役立つ情報を見逃してしまいます。

私たちは、必要なタイミングで、おすすめやお得な情報が届く体験を目指します。

### 製品説明（具体的な製品の説明）

**KAGO/OSは、お客さん・店舗・メーカーをつなぎ、買い物中の提案から販促の改善までを支えるプラットフォームです。** 利用する人と役割に応じて、KAGO/App・KAGO/Insight・KAGO/Adsの3つに分かれています。

| サービス | 対象 | 主な機能・役割 |
| --- | --- | --- |
| **KAGO/App** | スーパーで買い物をするお客さん | スマホで商品のバーコードを読み取り、かごを管理。買い物の内容や利用設定に合わせて、関連商品やクーポンを提案します。提案への反応・かごへの追加・疑似購入を、販促を振り返る情報につなげます。 |
| **KAGO/Insight** | 店長・店舗の販促担当者 | 店舗のおすすめやクーポンを設定し、メーカー広告の掲載を審査。表示・反応・購入などの指標を確認し、次の販促内容を見直すための店舗向け画面です。 |
| **KAGO/Ads** | 商品を届けたいメーカーの広告担当者、広告を募集する店舗担当者 | 店舗が広告を募集し、メーカーが広告素材と対象商品を登録・申請。掲載状況や公開範囲内の成果を確認し、次の広告を企画するための画面です。広告の掲載承認はInsightで行います。 |

クーポン配布は、買い物中に商品との出会いをつくる販促手段の一つです。通常のおすすめ・店舗の販促・メーカー広告を区別しながら、お客さんに役立つ提案を届けます。

#### 3つのサービスで回す販促のPDCA

**広告を出して終わりにせず、「計画 → 提案 → 結果確認 → 改善」をつなぐことがKAGO/OSの特長です。**

| 段階 | サービスのつながり |
| --- | --- |
| **Plan：計画する** | Insightで店舗の販促を設定。Adsで店舗が募集した広告にメーカーが素材・対象商品を申請し、Insightで掲載を承認します。 |
| **Do：届ける** | Appで買い物中のお客さんに、おすすめ商品・クーポン・承認済み広告を提案します。 |
| **Check：確かめる** | Appの表示・反応・かご追加・疑似購入の記録をもとに、店舗はInsightで、メーカーはAdsで公開範囲内の成果を確認します。 |
| **Act：改善する** | 店舗はInsightで販促内容を見直し、メーカーはAdsで広告素材や対象商品を見直して次の申請へつなげます。 |

```text
Plan：Insight・Adsで販促／広告を計画し、掲載を承認
  → Do：Appで買い物中に提案
  → Check：反応・かご追加・購入をInsight・Adsで確認
  → Act：販促内容・広告素材を見直す → 次のPlanへ
```

このPDCAは、3つのサービスが連携して目指す利用の流れです。各画面の実装と、全経路の接続・検証済み範囲は区別しています。購入はアプリ内の疑似購入を対象とし、外部POS連携・実決済は対象外です。「かご追加」はアプリ上の操作を指します。確認範囲とサンプルデータの扱いは[デモ構成・確認範囲](docs/development/demo-video.md)を参照してください。

### 特長

#### 1. スキャンする買い物の中で、商品を提案

商品スキャン・かご管理という買い物の操作に、関連商品のおすすめやクーポンを組み合わせます。広告を見るためだけの操作を増やさず、商品を選ぶタイミングで情報を届けることを狙います。今回の通知はAppを開いている間の画面内表示を対象とし、アプリを閉じていても届くプッシュ通知は対象外です。

#### 2. App・Insight・Adsをつなぎ、販促のPDCAを回す

店舗がInsightで設定・承認し、Appがお客さんに提案し、店舗とメーカーがInsight・Adsで結果を振り返る。一連の流れをつなげることで、広告の表示から反応・かご追加・購入までを、次の販促を考える判断材料にします。店舗の販促とメーカー広告の両方で、計画・実行・確認・改善を繰り返すことを目指します。

#### 3. 購入履歴を使った提案へ

同じ商品をかごに追加しても、購入履歴や利用設定に応じて提案を変えることに取り組んでいます。3人の架空利用者による比較を追加予定ですが、データの準備と、実際の配布ロジック・画面の接続確認は別の段階です。

### 解決できること・目指す価値

- **店員**：販促の設定から反応の確認までをつなぎ、施策を見直す判断材料を得る。
- **お客さん**：買い物中に関連商品やクーポンを知り、買い忘れやお得な情報の見逃しを減らす。
- **メーカー**：店舗への広告申請と掲載結果の確認を通じ、広告素材や対象商品の見直しにつなげる。

広告への反応と購入のつながりを可視化することを目指しており、売上向上や広告の因果効果を検証済みとするものではありません。

### 今後の展望

まず販促設定からAppの提案、反応・疑似購入の記録、Insightでの結果確認までの接続を仕上げます。その後、実店舗のPOS連携やプッシュ通知などを検討します。App・Insight・Adsを通じた記録と結果確認を充実させ、店舗・メーカーが繰り返し改善できる運用につなげます。店頭表示のKAGO/Signageとの連携も検証します。

### 注力したこと（こだわり等）

- お客さんにとって便利な買い物の流れに、商品提案を組み込むこと。
- 通常のおすすめ・店舗の販促・メーカー広告を区別し、提案の理由を伝えること。
- App・Insight・Adsをつなぎ、店舗とメーカーが販促のPDCAを回せる流れを設計すること。
- 実装・サンプルデータ・将来構想を分け、デモで確認できる範囲を明示すること。

## 開発技術

### 活用した技術

- Next.js、React、TypeScript、Tailwind CSS。
- Supabase：認証・共通DB（PostgreSQL）。
- `@zxing/browser`：スマートフォンのカメラによるバーコード読み取り。
- `bwip-js`・`sharp`：バーコード・アイコン生成。
- 動作確認用の架空の商品・顧客・購買履歴データ。
- デバイス：カメラ付きスマートフォン、店舗管理用PC。

### SIG-06：店内傾向による選定の先行確認

Adsを起動し、`/signage/selection-demo` を開くと、架空の「パスタ多め」「パン多め」と、少人数・集計なし・期限切れ・停止を切り替えて、選定理由・重み・ポリシー版を確認できます。ログは画面内の直近20件とダウンロードJSONに保持します。個人のかごや履歴、共有DBへの通信は使いません。
